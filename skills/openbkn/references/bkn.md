# bkn — knowledge networks

| Area | Commands |
|------|----------|
| KN | `list [--limit 1–1000\|-1]`, `get <kn> [--stats] [--export] [--branch b] [--detail-level full\|summary]`（`--detail-level` 目前只在带 `--export` 时有差别，且 summary 仍含完整定义）, `search <kn> <query> [--object-types ids] [--max-instances n] [--rerank]`（自然语言召回实例，附带命中对象类的定义）, `stats <kn>`, `export <kn>`, `create <name> [--branch b] [--import-mode normal\|overwrite\|ignore] [--no-strict-mode] [--binding-policy preserve\|detach]`（`--branch` 同时进 query 和 body）, `update <kn> --body [--branch b] [--import-mode m] [--no-strict-mode]`, `delete <kn> [--branch b]`, `subgraph <kn> --body [--query-type relation_path] [--branch b] [--include-logic-params] [--exclude-system-properties list] [--ignoring-store-cache]`. |
| Schema | `object-type|relation-type|action-type list/get/create/update/delete` (create/update take `--body`/`--body-file`); `action-type query/execute`. `list` takes `--branch`, `--name-pattern`, `--tag`; get/create/update/delete take `--branch`; create also takes `--import-mode normal|overwrite|ignore` and `--no-strict-mode`. A create body is `{entries:[…]}` (a bare array is wrapped). An update body carries `base_version`, the version it was read at; `--no-strict-mode` skips dependency checks. `object-type delete --force` deletes even when a relation type still binds it. `action-type query` takes `--include-type-info` / `--exclude-system-properties`; `action-type execute` takes `--branch`. |
| Metric / concept-group / schedules | `metric …` (`list --branch --name-pattern --tag`; `get`/`create`/`update`/`delete`/`validate --branch`; `create`/`validate --import-mode --no-strict-mode`, `update --no-strict-mode`; `get`/`delete` take comma-joined ids; `query`/`dry-run --branch --fill-null`), `concept-group …` (`list` returns every group unless `--limit`; `--name-pattern --tag --sort --direction --offset --branch`; `get --branch --stats --mode`; `create --branch --import-mode --no-strict-mode`, `update`/`add-members --branch --no-strict-mode`, `delete`/`remove-members --branch`), `action-log …` (`list --status --action-type-id --trigger-type --keyword (≤128 chars) --start-time-from/--start-time-to <ms> --limit (1–1000) --offset --need-total --search-after <cursor>`; `get --results-limit (1–1000) --results-offset --results-status`, offset + limit ≤ 10000; `cancel --reason`), `action-schedule …` (`list` returns every schedule unless `--limit`; `--name-pattern --action-type-id --status active\|inactive --sort --direction --offset --branch`; `get`/`create`/`update`/`set-status`/`delete` take `--branch`). (No KN-level build jobs — index builds are Vega build tasks, see [vega.md](vega.md).) |
| Capabilities | `capability list <kn> [--type skill\|function\|mcp_tool] [--box id] [--metadata-type openapi\|function] [--with-detail] [--sort create_time\|update_time] [--direction asc\|desc]`, `capability attach <kn> --skill ids \| --box id (--tool ids \| --all-tools) \| --mcp id (--tool names \| --all-tools)`, `capability detach <kn> <binding-ids>`. Bindings are what Context Loader recalls skills and tools from; a network with nothing bound recalls none. Binding is per tool: `--box` alone is refused, `--all-tools` binds the tools the box holds now (later additions show as `boxes[].unmounted_tools` in `list`). All take `--branch`. |
| Cypher | `cypher <kn> --query '<cypher>' [--params '<json object>'] [--branch b]` — read-only Cypher over the network's model, straight to bkn-backend and outside any Trace session. Same subset, limits and refusals as `context run-cypher`; answers `{columns, entries}`. |
| Paths / resources | `relation-type-paths <kn> --body [--branch b]`, `resources [--keyword s] [--limit n] [--offset n] [--sort f] [--direction asc\|desc]` (knowledge networks, the only resource type the backend recognizes → `{entries, total_count}`). `relation-type-paths` and the default (explore) mode of `subgraph` need `source_object_type_id` + `direction` (`forward` \| `backward` \| `bidirectional`) + `path_length` (1–3) in the body; leaving one out gets a 400. The bkn-backend contract's enum spells the reverse direction `reverse` while its description says `backward`; the CLI passes either through unchanged. `subgraph --query-type relation_path` takes `{"relation_type_paths":[{"object_types":[…],"relation_types":[…]}]}` instead. |
| Local package | `push <dir> [--import-mode normal\|overwrite\|ignore] [--no-strict-mode] [--binding-policy preserve\|detach]` (tar → import；0.1.5 部署目前接受但不生效 `--import-mode` / `--no-strict-mode`：同 id 重推总是覆盖，新 id 撞已有名字总是 403 `ObjectTypeNameExisted`), `pull <kn> [dir]` (export → extract), `validate <dir>` (offline structural check). `network.bkn` may declare `capabilities: {skills, functions, mcp_tools}`; push binds each by id, then by name, and skips — never fails on — one it cannot resolve: the answer's `capabilities.skipped` lists them and push repeats them on stderr. `validate` reports the entries no platform could resolve (`capabilities.skipped`) and a malformed section, which push would drop whole. |
| Build a KN | `create-from-catalog <catalog> --name <n> [--tables a,b] [--pk-map t:col]`. |

object-type query strategy (LLM): always pass a small `limit`, filter with `condition` — wide tables truncate JSON otherwise. Paging depends on the deploy: if the answer carries `paging.next_cursor` (deploys with foundry #1623), resend the query with `"cursor": "<paging.next_cursor>"` (null on the last page); if it has no `paging` (older deploys), page with body `offset`. Flags: `--branch`, `--include-type-info`, `--include-logic-params`, `--exclude-system-properties _instance_id,_instance_identity,_display`, `--ignoring-store-cache`.

PK detection (create-from-*): `--pk-map t:col` override → schema PK → sample cardinality; a composite schema PK is reported ambiguous (pick one with `--pk-map`) rather than guessed — guards silent data loss.

Table keys in `--tables` / `--pk-map` take the catalog's table name or a schema-qualified one (`yanfeng_kb.document` matches `document`); an unmatched key errors with the catalog's actual table list. Configure and build indexes through Vega. See [vega.md](vega.md).
