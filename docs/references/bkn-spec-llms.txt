Known structure
---------------
- Root file: network.bkn. `bkn_spec: "3.0"` in its frontmatter selects the 3.0 rules for the whole
  package; without it the package is read as 2.x and 3.0 declarations are ignored. Any other value
  is refused on import (`unsupported bkn_spec`).
- Subdirs: value_types/ (3.0), object_types/, relation_types/, action_types/, risk_types/,
  concept_groups/, object_metrics/ (`<id>@<version>.json`). The subdir decides the definition type;
  3.0 refuses a frontmatter `type` that differs.
- Optional CHECKSUM file inside the BKN dir (sibling of network.bkn); format 2 hashes frontmatter and
  body per definition; keys `network`, `<type>:<id>` (incl. `value_type:<id>`), `SKILL.md`.
- Packaging: macOS tar must set COPYFILE_DISABLE=1 to avoid ._* metadata files.

3.0 additions (spec section)
----------------------------
- One way to write each thing (§1.3): unknown frontmatter fields, `###` sections and columns,
  legacy column names, `condition:` wrappers, `Tool Configuration` are refused with a position.
- Lifecycle `lifecycle: {status, reason, replaced_by}` on object, relation and action types (§4.3).
- Property declarations (§6.8): Data Properties columns `Semantic`, `Required`, `Aliases`;
  `### Property Constraints` YAML keyed by property (`value_type`, `range`, `length`, `pattern`,
  `unit`, `unique`, `crs`, `timezone`); object type `aliases`.
- Relation declarations (§7.6): `reverse_name`, `aliases`, `importance`, `fallback_for`,
  `verification` in frontmatter; `Cardinality` column in `### Endpoint`; `### Relation Constraints`
  (`required`, `characteristics`); relation properties (`### Data Properties`,
  `### Property Constraints`) on indirect relations only.
- Action type `aliases` (§8.2).
- Value types `value_types/*.bkn` with a `### Definition` YAML (`base_type`, `enum`, `range`,
  `length`, `pattern`, `unit`) (§16).
- Full example: spec appendix C; SDK example skills/create-bkn/references/examples/clinic-lab/.
