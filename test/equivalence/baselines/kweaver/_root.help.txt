KWeaver SDK — operate KWeaver platform from CLI

USAGE
  kweaver [global flags] <command> <subcommand> [flags]
  kweaver --version | -V
  kweaver --help | -h

AUTHENTICATION & CONFIG
  auth    Login / switch / list saved platform credentials
  token   Print current access token (auto-refresh)
  config  Per-platform business-domain config

DECISION AGENT
  agent    Agent CRUD, chat, sessions, publish
  toolbox  Agent toolbox lifecycle
  tool     Tools inside toolbox

AI DATA PLATFORM
  bkn                       Knowledge network — build, query, action, metric
  resource (res)            Resources — list, find, get, query, delete
  dataflow                  Dataflow document workflows (run, runs, logs)
  vega                      Vega observability — catalog, resource, query
  context-loader (context)  MCP/HTTP context loader (reads BKN schema/instances)

TRACE AI
  trace  Diagnose conversations / build eval-sets / schema validate

FOUNDATION
  call (curl)  curl-style API call with auto-injected auth headers
  explore      Interactive web UI
  model        Model factory — LLM / small-model CRUD + chat
  skill        Skill registry / market
  help         Show help — use `help all` for full signatures

FLAGS
  --base-url <url>  Override platform URL  (env: KWEAVER_BASE_URL)
  --token <value>   Override access token (env: KWEAVER_TOKEN; disables write
                    commands)
  --user <id|name>  Use specific user credentials (env: KWEAVER_USER)
  --pretty          Pretty-print JSON output (default)
  --compact         Compact JSON output (pipeline-friendly)
  --help, -h        Show help
  --version, -V     Show version

ENVIRONMENT
  KWEAVER_PROFILE      Isolate active-platform/user state per shell
  KWEAVERC_CONFIG_DIR  Override config root (~/.kweaver)

EXAMPLES
  $ kweaver auth https://platform.example.com
  $ kweaver agent chat <agent_id> -m "hello"
  $ kweaver bkn build <kn-id> --wait

LEARN MORE
  Use `kweaver <command> --help` for command-specific help
  Use `kweaver help all` for full command signatures (migration fallback)
  For agents/multi-terminal: prefer `--user <id>` over `auth switch`
